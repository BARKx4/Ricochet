Ricochet v0.1.19-rc.7 Release Candidate Notes

A security-focused candidate with host-owned credentials, deferred HTTP secret resolution, stronger Windows PTY behavior, and two language-tooling compatibility fixes.

On this page Release Identity Host-Owned Secrets And HTTP Boundaries Runtime And CLI Corrections Governance And Packaging CI And Update Channel Current Boundaries Verification Checklist

Date: 2026-07-17

Ricochet v0.1.19-rc.7 advances the candidate line with a host-owned secret lifecycle and exact deferred-HTTP destination controls. It also carries Windows PTY reliability fixes, restores the documented != operator, and makes migration and seed commands resolve database URL environment placeholders consistently with serve.

Release Identity

  • The Ricochet release and tag identity is 0.1.19-rc.7 and v0.1.19-rc.7.
  • The public GitHub Debian asset is ricochet_0.1.19.rc.7_amd64.deb. Inside the package, Debian control metadata retains 0.1.19~rc.7 so exact prerelease ordering remains older than stable 0.1.19.
  • The supported desktop application lineage remains the native host shell with a WebView body and Ricochet-managed state. Public entry points remain rco gui, rco package --gui, and rco-gui.
  • The withdrawn native-control renderer experiment remains outside the supported WebView-only application surface.

Host-Owned Secrets And HTTP Boundaries

  • Host-owned session credentials are represented by opaque references rather than plaintext VM values. Secure action and prompt boundaries keep secret bytes outside ordinary Ricochet stack inspection and serialization.
  • Deferred HTTP credentials bind to exact destinations and resolve only inside the native send path. Failed requests, equality checks, diagnostics, and response handling do not disclose the underlying credential.
  • HTTP destination validation rejects documentation-only address ranges, fails closed when IPv6 allocation cannot be validated, and preserves the existing bounded host allowlist.
  • Credential scanners, session ownership checks, release-artifact resolution, and test-host gates fail loudly when their security assumptions are not met.
  • No production credential is embedded in this release. Live credentials remain external host inputs and are never release assets.

Runtime And CLI Corrections

  • Windows PTY creation no longer inherits an unrelated cursor state, and an explicitly empty environment serializes as a valid empty Windows environment block.
  • The lexer once again accepts != as the documented alias for not_equals? while continuing to reject removed leading-! word syntax.
  • rco migrate and rco seed resolve ${DATABASE_URL}-style placeholders through the same manifest resolver used by serve. Packaged SQLite keeps its raw literal-path safety check.
  • Secure-action type errors preserve their arguments, and equality rejects nested deferred credentials instead of accidentally traversing protected values.
  • The candidate retains exact mixed numeric comparison, bounded cycle handling for structural values, and the release probe coverage established by the prior runtime hardening pass.

Governance And Packaging

  • Ricochet first-party source, documentation, assets, crates, packages, and editor metadata remain under the Apache License 2.0 (Apache-2.0).
  • Locked dependency disclosures continue to ship as THIRD_PARTY_LICENSES.html and THIRD_PARTY_NOTICES.txt.
  • The public Learn manual, Reference Docs, packages, examples, and editor support remain part of package validation.
  • Release staging uses a clean tracked-source inventory so local untracked files cannot silently enter an archive or installer.
  • The Windows installer continues to reject foreign non-empty destinations, preserve unrelated user files, and validate installed binaries, docs, examples, notices, registration, shortcuts, and uninstall cleanup.

CI And Update Channel

  • CI builds and smokes Windows, Linux, Debian, macOS arm64, and macOS x64 artifacts before publication.
  • The release workflow creates a draft, audits exact asset names, sizes, SHA-256 digests, checksums, manifests, and freshly downloaded bytes, then publishes only after the audit passes.
  • SemVer prerelease tag v0.1.19-rc.7 is published as a GitHub prerelease, is not marked latest, and writes UPDATE-CHANNEL-candidate.json.
  • Candidate artifacts retain dry-run signing and notarization reports. Stable production signing still requires external Windows, Linux, and macOS credentials.

Current Boundaries

  • This repository commit prepares a candidate identity; the hosted workflow must still prove the exact tag, artifacts, and release state.
  • The candidate channel remains separate from the stable channel and does not replace the latest stable release.
  • Host-owned secret support is an infrastructure boundary, not permission for application code to print, persist, or serialize credentials.

Verification Checklist

Before creating the v0.1.19-rc.7 tag, run the repository gates from a clean checkout:

$version = "0.1.19-rc.7"

cargo metadata --locked --format-version 1
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo audit --deny warnings
pwsh -NoProfile -File .\scripts\validate-release-version.ps1
pwsh -NoProfile -File .\docs\reference\validate.ps1
pwsh -NoProfile -File .\scripts\validate-learn-manual.ps1 -RequireWordCoverage -RequireJekyllRawBlocks
pwsh -NoProfile -File .\scripts\validate-license-governance.ps1
pwsh -NoProfile -File .\scripts\acceptance.ps1

$releaseOut = Join-Path (Resolve-Path .\target).Path "rc-prep-smoke\$version\release-windows"
pwsh -NoProfile -File .\scripts\package-release.ps1 -Version $version -Target windows-x64 -OutDir $releaseOut -RequireInstaller -SigningMode dry-run
pwsh -NoProfile -File .\scripts\validate-release-artifacts.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version -RequireInstaller
pwsh -NoProfile -File .\scripts\validate-store-packaging.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version

After the release workflow completes, separately verify the published prerelease, tag commit, uploaded assets, combined checksums, platform manifests, signing-status reports, Debian control version, and candidate update-channel metadata.
