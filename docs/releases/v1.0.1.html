Ricochet v1.0.1 Release Notes

A stable patch release that restores random values on a fresh process.

On this page Release Identity Random Fix Stable Contract Packaging And Updates Verification Checklist

Date: 2026-10-06

Ricochet 1.0.1 fixes the random word returning zero on every call when its process-wide generator state started at zero. It preserves the public Ricochet 1.0 language and application contract.

Release Identity

  • The stable release and tag identities are 1.0.1 and v1.0.1.
  • The Linux package is ricochet_1.0.1_amd64.deb with Debian control version 1.0.1, providing a stable upgrade from 1.0.0.
  • Read the v1.0.0 release notes for the original stable contract and its platform boundaries.

Random Fix

  • The generator now steps from a nonzero seed while atomically comparing against its uninitialized zero state. Concurrent first calls share a valid generator state.
  • For n random with positive n, the result remains in 0..n-1. Zero is still a valid individual result; a bound of one always returns zero.
  • Cold-process and concurrent regression probes distinguish the original stuck-at-zero behavior from the corrected behavior. The change does not alter the syntax of random.

Stable Contract

The 1.0.0 WebView-only application surface, Apache-2.0 licensing, and Learn manual remain the stable baseline. This patch does not revise the prior mixed numeric correctness, cycle handling, release probe coverage, or clean tracked-source packaging policies.

Packaging And Updates

  • Official packages include LICENSE, THIRD_PARTY_LICENSES.html, and THIRD_PARTY_NOTICES.txt.
  • CI builds and audits the Windows installer, Linux tarball and Debian package, and macOS arm64/x64 archives before publication.
  • The stable annotated tag, Linux packages, and combined checksum inventory are GPG-authenticated. Verify SHA256SUMS.txt.asc using the published release key.
  • The stable update feed is UPDATE-CHANNEL-stable.json. Its verification metadata requires SHA-256 and Linux GPG checks, and advertises Windows Authenticode or Apple notarization only when produced.
  • Windows and macOS packages may be unsigned when platform certificates are unavailable. Their signing reports identify this fallback, and local security prompts may appear.

Verification Checklist

Before creating the GPG-signed v1.0.1 tag, run the repository gates from a clean checkout and perform the Windows package check through the same explicit fallback path used by CI:

$version = "1.0.1"

cargo metadata --locked --format-version 1
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo audit --deny warnings
pwsh -NoProfile -File .\scripts\validate-release-version.ps1
pwsh -NoProfile -File .\docs\reference\validate.ps1
pwsh -NoProfile -File .\scripts\validate-learn-manual.ps1 -RequireWordCoverage -RequireJekyllRawBlocks
pwsh -NoProfile -File .\scripts\validate-license-governance.ps1
pwsh -NoProfile -File .\scripts\acceptance.ps1

$releaseOut = Join-Path (Resolve-Path .\target).Path "release-prep-smoke\$version\release-windows"
pwsh -NoProfile -File .\scripts\package-release.ps1 -Version $version -Target windows-x64 -OutDir $releaseOut -RequireInstaller -SigningMode auto
pwsh -NoProfile -File .\scripts\validate-release-artifacts.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version -RequireInstaller
pwsh -NoProfile -File .\scripts\validate-store-packaging.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version

After CI publishes the release, independently verify the signed tag commit, latest published state, checksums, signatures, platform manifests and signing reports, Debian version, and stable update-channel metadata.
