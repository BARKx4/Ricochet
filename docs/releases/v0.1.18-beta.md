# Ricochet v0.1.18 Beta Release Notes

Date: 2026-06-19

Ricochet v0.1.18 is a beta security and platform release that supersedes
v0.1.17. It adds the new raw TCP and WebSocket development surface while
tightening the host-boundary checks around networking, package installation,
MVC manifests, retained processes, AI providers, databases, and editor startup.

## Highlights

- Raw socket words now cover bounded TCP and WebSocket connect/listen flows,
  including retained listeners, accepted connections, read/write/send, close,
  release, and runtime capability introspection.
- TCP, WebSocket, and HTTP host allow-lists pre-resolve destinations and reject
  DNS names that resolve to restricted addresses unless that restricted address
  was requested explicitly.
- WebSocket listeners can enforce browser `Origin` allow-lists, and WebSocket
  reads enforce caller-selected `max_bytes` caps under a global maximum.
- Static registry installs now require `https://` or `file://` registry URLs,
  reject absolute archive URLs in metadata, disable HTTP redirects, apply
  request timeouts, and cap archive entry count, entry size, and total unpacked
  size.
- MVC manifests now narrow operator-granted capabilities instead of granting
  themselves filesystem, process, PTY, HTTP, environment, AI, or database
  access. Packaged MVC GUI apps derive only bundle-bounded embedded grants from
  the packaged manifest.
- AI provider calls use no-redirect clients and capped response bodies.
  Database configuration requires allowed environment variables and explicit
  remote-host grants, and remote MySQL URLs require TLS unless they target a
  local development endpoint.
- Process and PTY command execution honors `--process-root` for command paths
  and working directories, so a bounded process grant cannot execute helpers
  outside its root.
- The v0.1.17 low-priority fixes remain covered: `NaN` is falsey, nonzero
  finite and infinite floats are truthy, and retained process, PTY, and HTTP
  stream release smoke tests poll readiness instead of sleeping a fixed delay.
- The VS Code extension ignores workspace Ricochet executable settings in
  untrusted workspaces and restarts the language server when trust is granted.

## Verification Checklist

Before tagging this release, run:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo audit --deny warnings
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\docs\reference\validate.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-editor-assets.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\acceptance.ps1
```

After the GitHub release workflow publishes artifacts, smoke-test the downloaded
Windows ZIP/installer, Linux tarball/Debian package, unsigned macOS tarballs,
and packaged CLI/GUI/TUI app outputs.
