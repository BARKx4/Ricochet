Ricochet v0.1.19-rc.4 Release Candidate Notes

Production-facing documentation for Ricochet developers.

On this page Breaking Language Cleanup Runtime, Compiler, And Tooling Updates Docs, Examples, And Editor Assets Changes Carried Forward Since v0.1.19-rc.3 Current Boundaries Verification Checklist

Date: 2026-07-03

Ricochet v0.1.19-rc.4 is a language-surface cleanup release candidate on the v0.1.19 train. It supersedes v0.1.19-rc.3 without replacing that immutable candidate tag, keeps the WebView desktop UI path as the supported app surface, and carries forward the packaging and security hardening work from earlier v0.1.19 candidates.

Breaking Language Cleanup

  • Collection mutators now use ordinary public word names: push, put, insert_at, remove, remove_at, and clear_items.
  • The old public bang-suffixed mutators are intentionally removed. The previous spellings were the six collection names with a trailing exclamation mark, and they no longer exist as compatibility aliases.
  • Leading-bang syntax, such as an exclamation mark before push, is rejected during lexing with an explicit diagnostic instead of being parsed as a special bang-word AST node.
  • insert_at avoids conflicting with Active Record insert, and clear_items avoids conflicting with the stack clear word.
  • Existing non-collection words such as stack clear, Active Record insert, fs_write_text, fs_delete, and tui_clear keep their public names.

Runtime, Compiler, And Tooling Updates

  • VM collection dispatch, built-in method existence checks, bytecode emission, formatter behavior, lint traversal, AST JSON output, LSP token handling, and compiler tests all use the new collection mutator names.
  • The old dedicated bang-word syntax node was removed from the lexer token model, AST, parser, formatter, compiler handling, lint traversal, LSP token handling, and AST JSON output.
  • Private capability method dispatch names were normalized where practical while preserving existing public global capability words.
  • CLI smoke tests now prove the new mutator names work and the old public bang names fail rather than silently aliasing.
  • The syntax test suite now covers rejection of leading-bang collection syntax.

Docs, Examples, And Editor Assets

  • Public reference docs, generated reference data, validation scripts, Learn manual chapters, wiki pages, examples, packages, scaffold templates, benchmark labels, and embedded Rust test strings were swept to the new names.
  • VS Code TextMate grammar and LSP completions now surface the non-bang collection mutators.
  • Word coverage data and rco words --check inventory expectations were updated so documentation, editor assets, and the embedded LSP inventory stay aligned.
  • The public website copy at try.ricochet.today was updated separately and promoted to production so the live docs match this release candidate.

Changes Carried Forward Since v0.1.19-rc.3

  • The native-control renderer experiment from rc.3 has been withdrawn from the current release surface before 1.0.
  • rco gui, rco package --gui, and the rco-gui launcher remain the supported desktop UI path.
  • Release packages include rco, rco-gui, and ricochet.
  • Post-rc.3 CI metadata now records newly observed transitive audit advisories explicitly so cargo audit --deny warnings can stay intentional rather than surprising.
  • README/documentation navigation cleanups after rc.3 are included in this candidate.

Current Boundaries

  • This is an intentional pre-public-language breaking cleanup. Code using the old collection bang names must be updated before running on rc.4.
  • Desktop UI for 1.0 is native shell plus WebView body plus Ricochet state.
  • The WebView app path still needs a richer first-party app-kit package for menu, dialog, table, split-pane, and command-palette workflows.

Verification Checklist

Before tagging this candidate, run:

$version = "0.1.19-rc.4"
$smoke = Join-Path (Resolve-Path .\target).Path "rc-prep-smoke\$version"
New-Item -ItemType Directory -Path $smoke -Force | Out-Null

cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo audit --deny warnings
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\docs\reference\validate.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-editor-assets.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-learn-manual.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\acceptance.ps1
rg 'push[!]|put[!]|insert[!]|remove[!]|remove_at[!]|clear[!]|Bang.?Word|[!]push' . --hidden --no-ignore --glob '!**/target/**' --glob '!.git/**' --glob '!.superpowers/**' -S

cargo build -p ricochet_cli --bins
.\target\release\rco.exe words --check --docs-app docs/reference/app.js --grammar editors/vscode/syntaxes/ricochet.tmLanguage.json
$guiHtml = Join-Path $smoke "webview-ui.html"
$env:RICOCHET_GUI_EXPORT_HTML = $guiHtml
.\target\release\rco.exe gui examples\webview_ui.rco
Remove-Item Env:\RICOCHET_GUI_EXPORT_HTML -ErrorAction SilentlyContinue
.\target\release\rco.exe package examples\webview_ui.rco --gui --output (Join-Path $smoke "WebviewUi.exe")
$env:RICOCHET_GUI_EXPORT_HTML = Join-Path $smoke "packaged-webview-ui.html"
& (Join-Path $smoke "WebviewUi.exe")
Remove-Item Env:\RICOCHET_GUI_EXPORT_HTML -ErrorAction SilentlyContinue
$releaseOut = Join-Path $smoke "release-windows"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-release.ps1 -Version $version -Target windows-x64 -OutDir $releaseOut -SigningMode dry-run
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-release-artifacts.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-store-packaging.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version

The stale-text rg command is expected to return no release-surface hits. If historical archived implementation plans mention old syntax, keep them separate from public examples and generated reference assets.

After the GitHub release workflow publishes artifacts, verify that the release is marked as a prerelease, is not marked latest, includes UPDATE-CHANNEL-candidate.json, and includes the Windows, Linux, and macOS packages plus checksum, signing-status, artifact-manifest, notary, and update channel reports.
