Ricochet v1.0.0 Release Notes

The first stable language, application, and packaging contract for Ricochet.

On this page Release Identity Language Contract Application Platform Security And Correctness Packaging And Updates Current Boundaries Verification Checklist

Date: 2026-07-20

Ricochet 1.0.0 promotes the hardened candidate line to a stable public contract. From this release onward, incompatible public language or application changes require a new major version under Semantic Versioning.

Release Identity

  • The stable release and tag identities are 1.0.0 and v1.0.0.
  • The Linux package is ricochet_1.0.0_amd64.deb with Debian control version 1.0.0, providing a direct stable upgrade from the candidate line.
  • The supported desktop application lineage is the native host shell with a WebView body and Ricochet-managed state. The withdrawn native-control renderer experiment remains outside the supported WebView-only application surface.

Language Contract

  • The postfix stack model, receiver-before-selector convention, underscore-separated public words, capitalized class declarations, and lowercase end form the stable source contract.
  • Exact symbolic operators such as != remain supported while obsolete bang-suffixed collection mutators stay removed.
  • The generated examples/words corpus contains one short app for every case-sensitive word in rco words --json. CI compiles all 372 apps, executes bounded deterministic examples, and links host-bound words to integration evidence.
  • The Learn manual covers the complete live word inventory and the reference, LSP, TextMate grammar, examples, and validator inventory are checked together.

Application Platform

  • MVC database capabilities expose postfix transaction, begin, commit, rollback, and savepoint methods with explicit Result behavior.
  • rco test installs a configured project database runtime before loading tests, so SQLite, PostgreSQL, MySQL, and MariaDB model query words exercise the same capability implementation used by served applications.
  • Configurable controller instruction budgets enforce a deployment ceiling, report usage, and publish staged cookies, sessions, and logs only after successful controller completion.
  • First-party packages cover portable UI documents, native WebView hosting, AI provider contracts, HTTP, processes and PTYs, sockets, approvals, filesystem/workspace access, packages, and SQLite-backed MVC applications.

Security And Correctness

  • Host-owned credential sessions, deferred secret references, exact network destinations, and bounded native send paths keep credentials out of Ricochet values and serialized task state.
  • Workspace operations enforce physical containment across links, and the sandbox protocol validates immutable policy, authenticated frames, coherent termination events, and backend conformance.
  • The stable line retains mixed numeric correctness, bounded cycle handling, release probe coverage, deterministic parser behavior, and clean tracked-source packaging.

Packaging And Updates

  • Ricochet source, documentation, assets, crates, packages, and editor metadata are licensed under the Apache License 2.0 (Apache-2.0).
  • Official packages include LICENSE, THIRD_PARTY_LICENSES.html, and THIRD_PARTY_NOTICES.txt.
  • The Windows installer, Linux tarball and Debian package, and macOS arm64/x64 archives are built, smoked, and audited before publication.
  • Stable publication requires production signing credentials: Windows Authenticode, Linux GPG signatures, and macOS codesigning plus Apple notarization.
  • The release is published as the latest non-prerelease GitHub release with UPDATE-CHANNEL-stable.json and production verification metadata.

Current Boundaries

  • The stable tag is not published until all platform signing and notarization credentials are configured and the hosted workflow proves the final assets.
  • SQLite transaction behavior is exercised locally. Live PostgreSQL and MySQL/MariaDB acceptance requires separately configured provider endpoints and credentials.
  • Application transactions cover database state only; coordinated transactions across HTTP, files, cookies, sessions, and logs are not implied.

Verification Checklist

Before creating the v1.0.0 tag, run the repository gates from a clean checkout and perform the platform package check with production credentials:

$version = "1.0.0"

cargo metadata --locked --format-version 1
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo audit --deny warnings
pwsh -NoProfile -File .\scripts\validate-release-version.ps1
pwsh -NoProfile -File .\docs\reference\validate.ps1
pwsh -NoProfile -File .\scripts\validate-learn-manual.ps1 -RequireWordCoverage -RequireJekyllRawBlocks
pwsh -NoProfile -File .\scripts\validate-license-governance.ps1
pwsh -NoProfile -File .\scripts\acceptance.ps1

$releaseOut = Join-Path (Resolve-Path .\target).Path "release-prep-smoke\$version\release-windows"
pwsh -NoProfile -File .\scripts\package-release.ps1 -Version $version -Target windows-x64 -OutDir $releaseOut -RequireInstaller -SigningMode require
pwsh -NoProfile -File .\scripts\validate-release-artifacts.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version -RequireInstaller
pwsh -NoProfile -File .\scripts\validate-store-packaging.ps1 -Target windows-x64 -OutDir $releaseOut -PackageVersion $version -RequireProduction
pwsh -NoProfile -File .\scripts\verify-release-signatures.ps1 -Target windows-x64 -OutDir $releaseOut -RequireProduction -ExpectedWindowsThumbprint $env:RICOCHET_WINDOWS_CERT_SHA1

After the workflow completes, independently verify the stable tag commit, latest published state, exact assets, combined checksums, platform manifests, production signing reports, Debian version, notarization reports, and stable update-channel metadata.
