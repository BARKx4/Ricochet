Getting Started

Production-facing documentation for Ricochet developers.

On this page Scripts Desktop GUI And TUI Showcase Apps

After installing rco, use it as the Ricochet toolchain:

rco new my_app
rco new --with-sqlite my_beta_app
rco routes my_app
rco migrate status my_beta_app
rco migrate apply my_beta_app
rco doctor my_app
rco verify my_app
rco lsp-diagnostics my_app/app/Models/User.rco --pretty
rco lsp
rco bench --smoke
rco doc my_app
rco test my_app

MVC apps serve static files from public/ at /assets by default. Override that with [web.static] dir = "..." and mount = "/..." in ricochet.toml.

Scripts

Run a script:

rco run examples/basic-oop.rco

Format, lint, and package a script:

rco fmt examples/basic-oop.rco
rco lint examples/basic-oop.rco
rco build examples/basic-oop.rco
rco run-bytecode build/app.rcob
rco emit-source build/app.rcob
rco package examples/basic-oop.rco --output basic-oop.exe

Desktop GUI And TUI

Preview and package a desktop GUI app:

rco gui examples/webview_ui.rco
rco package examples/webview_ui.rco --gui --output webview-ui.exe

Run and package an interactive terminal UI app:

rco tui examples/tui_counter.rco
rco package examples/tui_counter.rco --tui --output tui-counter.exe

Package an MVC app directory as a desktop beta build:

rco new my_desktop_app
rco package my_desktop_app --gui --mvc --output my-desktop-app.exe

MVC packaging uses the Git disclosure boundary when the project is in a worktree: tracked files plus untracked, non-ignored files are eligible. A standalone project, including a project root ignored by an enclosing worktree, keeps arbitrary source and asset layouts by packaging its ordinary files recursively. In both modes Ricochet omits Git metadata, .env variants (safe .env.example, .env.sample, and .env.template files remain eligible), SQLite databases and sidecars, and the output executable. Symbolic links and private-key or credential file shapes stop packaging with an error. Audit a standalone project tree before packaging because it has no Git ignore boundary.

A packaged file-backed SQLite app must provide at least one migration under db/migrations. Ricochet never embeds db/development.sqlite3 or uses its rows as install data. On launch it applies migrations to per-user application data keyed by package.name and the installed executable path. Replacing the executable at the same path preserves data; copying, moving, or renaming it intentionally creates a separate data identity. RICOCHET_MVC_DATA_HOME can set an absolute base directory for controlled deployments and tests.

Use --output webview-ui on Linux and macOS. GUI launchers open native embedded WebView windows on Windows, macOS, and Linux. Current Linux launchers need GTK 3, WebKitGTK 4.1, and libxdo 3 runtime libraries; generated Debian packages declare those dependencies.

On Linux, the same package command can also create portable tarballs or Debian packages for a .rco file:

rco package examples/basic-oop.rco \
  --output basic-oop \
  --linux-package tar \
  --linux-package deb \
  --package-name basic-oop \
  --package-version 0.1.0

Showcase Apps

Explore the beta showcase apps:

rco check examples/showcase/sqlite_notes
rco run examples/showcase/package_auth_forms/main.rco
rco run examples/showcase/ai_provider_probe/main.rco
rco gui examples/showcase/gui_task_monitor.rco
rco debug --step examples/showcase/debugger_demo.rco

See examples/showcase/README.md for the SQLite notes MVC app, first-party package consumer, AI provider probe, GUI v2 task monitor, and debugger demo.
